What this deployment does, exactly. It measures and it records. It does not settle. A bond is recorded as forfeited and no trader is paid, because the payout path was cut under this project's own kill criteria when the submission window got short. Nothing here implies anyone was made whole.

THE VERDICT FUNCTION, RUN IN YOUR BROWSER

Not chain data. This runs the same pure evaluator the contract runs, on numbers you choose, so you can see the states change. Move the spread past the committed bound.

Instant reactive sampling

A subscription on the pool wakes the registry when the market emits. Validators invoke the handler, it reads the book at that instant, and the sample is written on chain. Nobody sends a transaction to make it happen.

Zero-trust stranger verification

The verdict is a pure function of a stored sample and a stored commitment. Anyone can read both from a public RPC and re-derive it with a second implementation, which is what pnpm claim:verify does.

The anti-dashboard

Gaps are recorded as NOT_SAMPLED and are never folded into coverage. A window that was 90% unsampled is reported as a window that was 90% unsampled.

Measurement, not a promise

COVERED_AT_SAMPLE is the strongest positive state that exists. It means the envelope held at one instant. It does not mean the book held between two instants, and nothing here says it does.

What is measured, and what is not

Read this before quoting any number on this site.

Assize measures at instants, not continuously. A sample is one reading at one block. It is not a window, not an average, and not proof that the book held between two samples.
The sample count is not the observation count. The subscription matches every log the pool emits, so a block with many pool events produces many samples reading the same book at the same instant. None is fabricated; they are redundant. The honest measure is the distinct-block count, and both are shown.
Nobody was paid. A forfeited bond stays in the registry. There is no settlement function in this deployment at all.
The maker is us. Labelled PROJECT_BASELINE wherever it appears. Not a third party, not adoption, not demand. It published a commitment it did not keep, which is what it exists to do.
The block pin is a parent hash. A contract cannot observe the hash of the block it is running in, so a sample stores block N with the hash of N−1. Check it as cast block N --field parentHash. A verifier that treats it as a block hash will reject every honest sample.
A keeper, if one were ever registered, is trusted while used. Its only defence is that every sample pins a block. That is a real defence against writing false values and a weak one against choosing moments. No keeper is registered.
